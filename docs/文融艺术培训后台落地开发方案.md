# 文融艺术培训后台落地开发方案

> 文档状态：开发前规划稿  
> 适用项目：文融艺术培训 UniApp + RuoYi-Vue-Pro 后端  
> 使用方式：前端页面完成后，按本文档分阶段实现后台接口、数据库和管理端

## 1. 建设目标

建设一套面向文融艺术培训机构的运营后台，使管理员和各校区工作人员可以独立维护：

- 线下校区、教室、教师和班级
- 线上课程、线下课程、章节和课程文件
- 课程商品、教材教具、价格、库存和上下架
- 首页轮播、课程推荐、活动和公告
- 学员、报名关系、订单、学习进度和签到
- 文件上传、权限控制、审核发布和操作记录

小程序只负责展示和使用数据，课程、商品和文件内容统一由后台维护，避免后续每次修改内容都重新发布小程序。

## 2. 当前项目基础与复用策略

当前后端已经存在可复用能力，优先扩展现有模块，不重复造轮子。

### 2.1 教育模块

已有课程、章节、视频、课程内容、学员、学习进度、签到和通知相关代码。重点复用：

- `yudao-module-education/yudao-module-education-biz`
- `EduCourseController`
- `EduCourseContentController`
- `EduCourseCategoryController`
- `EduCourseChapterDO`
- `EduCourseVideoDO`
- `EduCourseProgressDO`
- `EduCourseAttendanceDO`

### 2.2 商品模块

已有商品分类、SPU、SKU、品牌、库存和订单能力。课程商品建议继续使用商品中心，通过课程和商品关联实现“课程内容”和“售卖商品”分离。

- `yudao-module-mall/yudao-module-product`
- `ProductSpuController`
- `ProductSkuDO`
- `ProductCategoryDO`

### 2.3 文件模块

已有文件上传、文件配置、对象存储和 App 文件上传接口。课程资料不要直接存进业务表，业务表只保存文件 ID、类型和展示信息。

- `yudao-module-infra`
- `FileController`
- `FileService`
- `FileConfigDO`
- `AppFileController`

### 2.4 现有小程序端

当前课程页已经支持线上/线下切换和 8 个线下校区的前端演示数据。后台接入时需要将本地静态数据替换为接口数据，并使用校区 ID，不要长期使用校区名称作为关联字段。

## 3. 角色与数据权限

“顾客自己管理商品”在系统中建议落地为“机构管理员或校区工作人员管理”。普通学员不能修改商品、课程和课程文件。

| 角色 | 数据范围 | 主要权限 |
| --- | --- | --- |
| 平台超级管理员 | 全部机构和校区 | 系统配置、机构、权限、全部业务数据 |
| 机构管理员 | 本机构全部校区 | 校区、课程、商品、文件、学员、订单 |
| 校区负责人 | 指定校区 | 本校区课程、班级、教师、学员、签到 |
| 内容编辑 | 授权课程 | 课程介绍、章节、视频、PDF、PPT、习题 |
| 教师 | 授课课程 | 教学资料、作业、课后内容、学员进度 |
| 客服/招生 | 授权业务范围 | 学员咨询、报名、订单、售后 |
| 财务 | 机构级 | 商品价格、订单、退款、支付对账 |
| 学员 | 个人数据 | 浏览、购买、学习、签到、下载授权资料 |

权限设计要求：

1. 后台账号必须保留登录和 RBAC 权限，不能沿用小程序真机测试时的免登录逻辑。
2. 校区负责人只能看到授权校区的数据。
3. 文件下载必须校验用户是否拥有对应课程权限。
4. 商品上下架、价格变更、课程发布和文件删除记录操作人和时间。
5. 已产生订单的商品不允许直接删除，使用下架或停用。

## 4. 核心业务模块

### 4.1 校区/线下机构管理

初始校区：

1. 文山总校
2. 砚山分校
3. 广南分校
4. 富宁分校
5. 五北分校
6. 马吴分校
7. 西畴分校
8. 麻栗坡分校

后台字段建议：

- 校区名称、校区编码、校区类型（总校/分校）
- 联系电话、详细地址、地图经纬度
- 校区负责人、营业状态
- 校区 Logo、环境图片、简介
- 教室列表及教室容量
- 排序值、是否显示

状态建议：`启用`、`停用`。停用校区不能新报名，但历史订单和历史课程仍可查询。

### 4.2 课程管理

课程必须区分：

- 线上课程：直播、录播、双师互动
- 线下课程：校区、班级、教室、上课时间、教师

课程基础字段：

- 课程名称、课程副标题、封面、详情富文本
- 课程类型、科目、年龄段、适用年级
- 课程标签、授课教师、课程简介
- 关联商品 SPU/SKU
- 课程状态、排序、推荐标记
- 预计课时、有效期、试看设置

线下课程字段：

- 校区 ID
- 班级 ID
- 教室 ID
- 上课周期和星期
- 上课开始/结束时间
- 班级容量、已报名人数
- 班主任和授课教师
- 到校签到规则

线上课程字段：

- 直播/录播类型
- 直播房间或第三方课堂标识
- 视频总时长
- 是否允许回放
- 回放有效期
- 试看章节

课程状态建议：`草稿`、`待审核`、`已发布`、`已下架`、`已结束`。

### 4.3 章节与课程文件

课程内容采用树形结构：课程 → 章节 → 课时/资料。

支持的内容类型：

- 视频
- 音频
- PDF
- PPT/PPTX
- Word
- 图片
- ZIP 习题包
- 外部直播地址
- 富文本课件

每个文件或课时需要保存：

- 文件 ID、原始文件名、文件类型、文件大小
- 存储地址或对象存储 Key
- 所属课程、章节、课时
- 是否试看、是否允许下载
- 展示排序、发布状态
- 上传人、上传时间、删除时间

上传流程：

1. 后台选择文件并校验扩展名、MIME、大小。
2. 上传到统一文件中心或对象存储。
3. 文件中心返回文件 ID。
4. 业务表保存课程、章节和文件的关联关系。
5. 发布课程时检查必填资料和文件状态。
6. 学员端通过短期签名地址访问私有文件。

大文件建议支持分片上传、断点续传和上传进度。视频、PDF 等内容默认不使用永久公开 URL。

### 4.4 商品管理

商品中心建议分为：

- 课程商品：线上课、线下班、体验课、套餐课
- 教材商品：课本、练习册、教具
- 服务商品：测评、咨询、报名服务

商品字段：

- 商品名称、主图、轮播图、详情内容
- 商品分类、商品类型
- 原价、销售价、划线价
- SKU、规格、库存、库存预警
- 关联课程、关联校区
- 是否支持退款、是否需要物流
- 上下架时间、排序、推荐位

课程商品购买成功后，需要自动生成学员课程权益；教材和教具商品走商城订单和物流流程。二者不能混用同一套发货逻辑。

### 4.5 首页和运营内容管理

后台维护以下内容：

- 首页轮播图
- 热门课程
- 校区推荐
- 限时活动
- 公告和喜报
- 常用服务入口
- 商品推荐
- 课程分类和排序

建议增加开始时间、结束时间、上下架状态和排序字段，避免每次活动都修改代码。

### 4.6 学员、订单和课程权益

后台需要能查询：

- 学员基本资料和监护人信息
- 学员所属校区
- 已购买商品
- 已开通课程
- 学习进度和最后学习时间
- 线下班级和签到记录
- 退款、售后、优惠记录

课程权益建议独立建模，不直接根据订单状态临时判断。这样可以支持赠课、补课、转班、有效期和人工开通。

## 5. 建议数据表

以下为新增或扩展方向，最终以现有数据库表结构为准。

### 5.1 校区相关

- `edu_campus`：校区主表
- `edu_campus_classroom`：教室表
- `edu_campus_staff_rel`：校区与员工关系

### 5.2 课程相关

- 扩展现有 `edu_course`：课程类型、校区、发布状态、商品关联等
- 扩展现有 `edu_course_chapter`：章节排序和发布状态
- 扩展现有 `edu_course_video`：文件 ID、试看、下载权限
- `edu_course_material`：PDF、PPT、图片、习题等非视频资料
- `edu_course_class`：线下班级和排课
- `edu_course_class_student`：班级与学员关系
- `edu_course_teacher_rel`：课程与教师关系
- `edu_course_campus_rel`：课程与校区关系

### 5.3 权益与运营

- `edu_student_course`：学员课程权益
- `edu_course_publish_record`：课程发布审核记录
- `edu_operation_log`：重要业务操作记录
- `edu_home_content`：首页运营内容

商品和文件优先复用现有商品表、订单表和基础文件表，只有现有字段无法表达业务时再扩展。

## 6. 建议接口

接口命名沿用当前 RuoYi-Vue-Pro 的 `/admin-api` 和 `/app-api` 规范。

### 6.1 管理端接口

```text
GET    /admin-api/education/campus/page
POST   /admin-api/education/campus/create
PUT    /admin-api/education/campus/update
DELETE /admin-api/education/campus/delete
GET    /admin-api/education/campus/list

GET    /admin-api/education/course/page
GET    /admin-api/education/course/get
POST   /admin-api/education/course/create
PUT    /admin-api/education/course/update
PUT    /admin-api/education/course/publish
PUT    /admin-api/education/course/disable

GET    /admin-api/education/course-content/tree
POST   /admin-api/education/course-content/save
DELETE /admin-api/education/course-content/delete
POST   /admin-api/education/course-content/reorder

POST   /admin-api/infra/file/upload
GET    /admin-api/infra/file/page
DELETE /admin-api/infra/file/delete

GET    /admin-api/product/spu/page
POST   /admin-api/product/spu/create
PUT    /admin-api/product/spu/update
PUT    /admin-api/product/spu/update-status
```

### 6.2 小程序端接口

```text
GET /app-api/education/campus/list
GET /app-api/education/course/list?courseType=ONLINE
GET /app-api/education/course/list?courseType=OFFLINE&campusId=...
GET /app-api/education/course/get?id=...
GET /app-api/education/course/outline?id=...
GET /app-api/education/course/material/url?id=...
GET /app-api/education/student-course/list
POST /app-api/education/attendance/check-in
```

小程序端只返回已发布内容，不返回草稿、待审核、停用文件和后台管理字段。

## 8. 开发阶段

### 第 0 阶段：环境和权限准备

- 确认数据库、Redis、对象存储和后台账号
- 确认机构是否使用多租户
- 保持后台登录鉴权开启
- 创建教育、商品、文件相关菜单权限
- 确认测试环境和正式环境文件存储隔离

### 第 1 阶段：校区和课程基础

- 建立 8 个校区数据
- 完成校区增删改查和启停用
- 完成课程类型、课程分类和课程基础信息
- 后台可以创建线上课程和线下课程
- 小程序课程页改为调用后台课程接口

### 第 2 阶段：章节、文件和发布

- 完成章节树
- 完成视频、PDF、PPT、图片等文件上传
- 完成文件与章节关联
- 完成草稿、审核、发布、下架
- 学员端按课程权限访问文件

### 第 3 阶段：商品和报名

- 完成课程关联商品
- 完成价格、SKU、库存、上下架
- 购买成功自动开通课程权益
- 增加报名、退款和人工开通入口

### 第 4 阶段：线下教学

- 班级、教室、教师、排课
- 学员转班、请假、补课
- 校区签到和签到统计
- 校区负责人数据权限

### 第 5 阶段：运营和统计

- 首页内容装修
- 活动、优惠券、团购
- 学员转化、销售、课程完成率
- 校区经营数据和教师教学数据

## 9. 文件上传安全要求

- 限制扩展名、MIME 类型和单文件大小
- 视频和大文件使用分片上传
- 私有文件使用短期签名地址
- 文件删除采用软删除，避免误删后无法恢复
- 记录上传人、关联课程和访问权限
- 生产环境建议增加病毒扫描和敏感内容审核
- 不允许前端直接拼接内部存储路径
- 课程资料下载必须先校验课程权益

## 10. 小程序端改造要求

当前课程页中的静态 `campusOptions` 和 `offlineCourses` 只用于演示，正式接入后台后需要：

1. 新增 `getCampusList()` 接口。
2. 选择校区后保存 `campusId`，不保存校区名称。
3. 调用 `getCourseList({ courseType: 'OFFLINE', campusId })`。
4. 课程详情从后台读取章节和资料。
5. 线上和线下课程使用同一课程入口，但根据 `courseType` 展示不同字段。
6. 未发布课程和未授权课程资料不在小程序显示。
7. 前端免登录只保留在开发环境，发布前通过环境变量重新开启鉴权。

## 11. 验收标准

### 校区

- 后台可以维护 8 个校区。
- 小程序可以切换校区并看到对应线下课程。
- 停用校区不能新增报名。
- 校区负责人只能看到本校区数据。

### 课程

- 管理员可以分别创建线上和线下课程。
- 课程可以保存草稿、提交审核、发布和下架。
- 线下课程必须绑定校区、班级、教室和上课安排。
- 线上课程可以绑定视频、直播或录播资料。

### 文件

- 管理员可以上传视频、PDF、PPT、图片和习题文件。
- 文件可以绑定章节并调整顺序。
- 学员只能访问已购买且已发布课程的资料。
- 删除文件不会破坏历史课程记录。

### 商品

- 管理员可以维护课程商品和教材教具商品。
- 商品可以设置价格、SKU、库存和上下架状态。
- 购买课程商品后能自动生成课程权益。
- 已有订单的商品不可直接删除。

## 12. 开始开发前需要确认的事项

- 后台是否需要多机构/多租户，还是只有文融艺术培训一个机构
- 8 个校区是否需要各自独立运营和独立数据权限
- 视频文件准备存储在本地、MinIO、阿里云 OSS、腾讯云 COS 还是其他对象存储
- 单个视频和课程资料的大小限制
- 是否需要课程发布审核
- 线上直播准备接入哪一家直播服务
- 课程商品是否允许拼团、优惠券和分期
- 线下课程是否需要完整排课、调课、请假和补课

以上事项确认后，再进行数据库设计和接口编码，避免后续因为存储、权限或订单规则变化而返工。
